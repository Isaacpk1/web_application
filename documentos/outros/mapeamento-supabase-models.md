# Mapeamento Supabase x Models - Backend G04

Este documento descreve o schema real do banco de dados Supabase e o mapeamento para os tipos TypeScript do projeto.

**Fonte de verdade TypeScript:** `src/database/SupabaseSchema.ts` (tipos de linha que refletem o DDL diretamente).

**Modelos de dominio:** `src/models/domain/` (tipos de negocio derivados das linhas do banco).

---

## 1. Tabelas e DDL

### 1.1. `setor`

```sql
CREATE TABLE setor (
  id      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nome_regiao VARCHAR(100) NOT NULL,
  tipo_risco  VARCHAR(100) NOT NULL,
  grau_risco  VARCHAR(50)  NULL CHECK (grau_risco IN ('Baixo', 'Médio', 'Alto', 'Muito Alto'))
);
```

### 1.2. `cadastrador`

```sql
CREATE TABLE cadastrador (
  id        SERIAL PRIMARY KEY,
  nome      VARCHAR(150) NOT NULL,
  documento VARCHAR(50)  NOT NULL UNIQUE, -- formato: '123.456-7'
  email     VARCHAR(150) NULL
);
```

### 1.3. `casa`

```sql
CREATE TABLE casa (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_setor        BIGINT NOT NULL REFERENCES setor(id) ON DELETE RESTRICT,
  coordenada_lat  DECIMAL(10, 8) NOT NULL,
  coordenada_long DECIMAL(11, 8) NOT NULL,
  logradouro      VARCHAR(150) NOT NULL,
  numero          VARCHAR(20)  NOT NULL,  -- aceita 'S/N', 'Lote 4', etc.
  observacao      TEXT         NULL,
  bairro          VARCHAR(100) NOT NULL,
  cep             CHAR(8)      NULL,
  tipo_construcao VARCHAR(50)  NOT NULL CHECK (tipo_construcao IN ('Madeira', 'Alvenaria', 'Misto')),
  uso_imovel      VARCHAR(50)  NOT NULL CHECK (uso_imovel IN ('Residencial', 'Comercial', 'Misto')),
  status_imovel   VARCHAR(50)  NOT NULL DEFAULT 'Sadio'
                               CHECK (status_imovel IN ('Sadio', 'Interditado', 'Destruido')),
  data_interdicao DATE NULL
);
```

### 1.4. `nucleo_familiar`

```sql
CREATE TABLE nucleo_familiar (
  id                        BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nome_nucleo               VARCHAR(150)   NOT NULL,
  id_casa                   BIGINT         NOT NULL REFERENCES casa(id) ON DELETE RESTRICT,
  id_cadastrador            BIGINT         NULL REFERENCES cadastrador(id) ON DELETE RESTRICT,
  id_chefe_familia          BIGINT         NULL,  -- FK ciclica definida apos criar individuo
  observacao                TEXT           NULL,
  tempo_residencia_domicilio NUMERIC(10,2) NULL,
  tempo_residencia_area      NUMERIC(10,2) NULL,
  tempo_residencia_municipio NUMERIC(10,2) NULL,
  renda_familiar_total       DECIMAL(10,2) NOT NULL DEFAULT 0.00
);
```

### 1.5. `individuo`

```sql
CREATE TABLE individuo (
  id                   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_nucleo_familiar   BIGINT       NOT NULL REFERENCES nucleo_familiar(id) ON DELETE CASCADE,
  nome_completo        VARCHAR(255) NOT NULL,
  apelido              VARCHAR(255) NULL,
  nome_social          VARCHAR(255) NULL,
  data_nascimento      DATE         NOT NULL,
  genero               VARCHAR(50)  NOT NULL CHECK (genero IN ('Masculino', 'Feminino', 'Outro')),
  cor_raca             VARCHAR(50)  NULL CHECK (cor_raca IN ('Branco', 'Preto', 'Pardo', 'Amarelo', 'Indigena')),
  uf                   CHAR(2)      NULL,
  estado_civil         VARCHAR(50)  NULL CHECK (estado_civil IN ('Solteiro', 'Casado', 'Viuvo', 'Divorciado')),
  profissao            VARCHAR(100) NULL,
  nome_mae             VARCHAR(255) NULL,
  nome_pai             VARCHAR(255) NULL,
  grau_parentesco      VARCHAR(100) NULL,
  escolaridade         VARCHAR(100) NULL,
  situacao_ocupacional VARCHAR(100) NULL,
  cpf                  CHAR(11)     NULL UNIQUE,
  doc_estrangeiro      VARCHAR(50)  NULL,
  rg                   VARCHAR(20)  NULL,
  nis                  CHAR(11)     NULL UNIQUE,
  telefone             VARCHAR(20)  NULL,
  email                VARCHAR(255) NULL,
  status_vital         VARCHAR(50)  NOT NULL DEFAULT 'Vivo'
                                    CHECK (status_vital IN ('Vivo', 'Obito', 'Desaparecido')),
  data_obito           DATE         NULL,
  semanas_gestacao     SMALLINT     NULL
);

-- Vinculo ciclico: chefe da familia pertence ao proprio nucleo
ALTER TABLE nucleo_familiar
  ADD CONSTRAINT fk_nucleo_chefe_familia
  FOREIGN KEY (id_chefe_familia) REFERENCES individuo(id) ON DELETE SET NULL;
```

### 1.6. `vulnerabilidade`

```sql
CREATE TABLE vulnerabilidade (
  id                   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  tipo_vulnerabilidade VARCHAR(50) NOT NULL UNIQUE
    CHECK (tipo_vulnerabilidade IN ('Idoso', 'Gestante', 'PCD', 'Lactante', 'DoencaCronica', 'Crianca'))
);
```

### 1.7. `individuo_vulnerabilidade` (tabela pivo N:N)

```sql
CREATE TABLE individuo_vulnerabilidade (
  id_individuo      BIGINT REFERENCES individuo(id) ON DELETE CASCADE,
  id_vulnerabilidade BIGINT REFERENCES vulnerabilidade(id) ON DELETE CASCADE,
  PRIMARY KEY (id_individuo, id_vulnerabilidade)
);
```

### 1.8. `pet`

```sql
CREATE TABLE pet (
  id                 BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_nucleo_familiar BIGINT NOT NULL REFERENCES nucleo_familiar(id) ON DELETE CASCADE,
  tipo               VARCHAR(100) NULL,
  porte              VARCHAR(50)  NULL,
  imagem             TEXT         NULL,
  quantidade         SMALLINT     NULL
);
```

## 2. Mapeamento Tabela → TypeScript

| Tabela SQL | Schema TypeScript (`SupabaseSchema.ts`) | Dominio (`models/domain/`) | DTO de criacao | DTO de atualizacao |
| --- | --- | --- | --- | --- |
| `setor` | `Setor` | `Setor` | `CreateSetorDTO` | `UpdateSetorDTO` |
| `cadastrador` | `Cadastrador` | `Cadastrador` | `CreateCadastradorDTO` | `UpdateCadastradorDTO` |
| `casa` | `Casa` | `Casa` | `CreateCasaDTO` | `UpdateCasaDTO` |
| `nucleo_familiar` | `NucleoFamiliar` | `NucleoFamiliar` | `CreateNucleoFamiliarDTO` | `UpdateNucleoFamiliarDTO` |
| `individuo` | `Individuo` | `Individuo` | `CreateIndividuoDTO` | `UpdateIndividuoDTO` |
| `vulnerabilidade` | `VulnerabilidadeRow` | `Vulnerabilidade` | `CreateVulnerabilidadeDTO` | `UpdateVulnerabilidadeDTO` |
| `individuo_vulnerabilidade` | `IndividuoVulnerabilidade` | `IndividuoVulnerabilidade` | — | — |
| `pet` | `Pet` | `Pet` | `CreatePetDTO` | `UpdatePetDTO` |

### Diferencas entre `SupabaseSchema` e `models/domain`

- `SupabaseSchema` usa `string` para campos de enum (ex.: `genero: string`), pois reflete diretamente o banco.
- `models/domain` usa union types (ex.: `genero: 'Masculino' | 'Feminino' | 'Outro'`), garantindo tipagem no TypeScript.
- Repositories fazem o cast de `string` (do Supabase) para o union type do dominio via `as`.
- A coluna `VulnerabilidadeRow` no schema tem esse nome para evitar colisao com o tipo de dominio `Vulnerabilidade`.

## 4. Convencoes de nomenclatura

- Nomes de tabela: `snake_case`, singular.
- PKs: sempre `id BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- FKs: `id_<tabela>` (ex.: `id_setor`, `id_nucleo_familiar`).
- Booleanos nullable: usados para campos opcionais que podem ser desconhecidos.
- Enums: implementados como `CHECK` no banco e como union types no TypeScript.
